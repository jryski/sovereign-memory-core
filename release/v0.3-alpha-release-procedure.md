# v0.3-alpha exact-release procedure

This procedure exists to prevent the last release step from invalidating the
coordinates that were reviewed. It does not itself authorize merge, tagging,
deployment, HOUSE mutation, or a release declaration.

## 1. Freeze the release candidate

Record the exact 40-character commit SHA and tree SHA. No code, documentation,
workflow, manifest schema, or release file may change after the evidence set is
accepted without creating a new candidate and rerunning the applicable gates.

The candidate must have current passing receipts for:

- work-memory conformance;
- C1 perimeter evaluability on PostgreSQL 15/16;
- C2 independent clean provider-exit restore;
- executable schema drift comparison;
- release-candidate manifest/checksum generation and verification;
- the immutable PERSONAL nine-row/hash reconciliation;
- independent exact-head review;
- HOUSE rollback-safe acceptance with its required independent recovery anchor.

The parent #55 owner-release authorization remains separate and final.

## 2. Preserve the reviewed SHA through integration

Do **not** squash, rebase, amend, or otherwise rewrite the reviewed candidate.

If repository policy permits an explicitly authorized fast-forward of `main` to
the reviewed candidate, verify immediately afterward that `main` resolves to the
same exact commit and tree.

If the integration method creates a new merge/squash/rebase commit, that new
commit is a **new release candidate**. Do not tag it by inheritance. Rerun the
release-critical workflows, regenerate release artifacts, and obtain the
required exact-commit review/authorization for that new coordinate.

## 3. Generate release artifacts from the exact candidate

Run `scripts/build_release_candidate.py` against the exact checked-out candidate.
The builder is evidence-only. It does not create a tag or release.

Required generated assets:

- `sovereign-memory-core-v0.3-alpha.tar.gz`;
- `RELEASE_MANIFEST.json`;
- `CHECKSUMS.sha256`;
- `KNOWN_LIMITATIONS.md`;
- `PROVIDER_EXIT_RECEIPT.json`;
- `PROVIDER_EXIT_FIXTURE.bundle.tar`;
- `SCHEMA_DRIFT_RECEIPT.json`.

Run `sha256sum -c CHECKSUMS.sha256` from the asset directory and retain the
verification output with the release receipt.

The source archive is built with `git archive`; the builder verifies the commit
ID embedded in the tar stream before compression. The manifest records the exact
commit and tree used to build it.

## 4. Owner authorization

Before creating any release tag, obtain Jesse's explicit final release
authorization against the frozen coordinate and summarized gate receipt. This is
the owner decision required by parent #55.

## 5. Tag exactly what was authorized

The candidate tag name for this program is `v0.3-alpha`. If the owner chooses a
different release tag, regenerate the release manifest/assets with that version
before publication.

The tag must resolve to the exact authorized release commit. Verify both before
and after publication:

```text
git rev-parse HEAD
git rev-parse v0.3-alpha^{commit}
git rev-parse HEAD^{tree}
git rev-parse v0.3-alpha^{tree}
```

Both commit outputs must be identical and both tree outputs must be identical.
A tag pointing at an ancestor, successor, synthetic PR merge ref, or unreviewed
merge commit does not satisfy the gate.

Do not move a published release tag to repair a bad coordinate silently. Treat a
mistag as a release incident, record it, and use an explicit corrected version
or other owner-approved remediation.

## 6. Publish without widening the claim

Publish the exact generated manifest/checksums/limitations with the tagged
source artifact. The release description must not claim more than the recorded
gates establish. In particular, do not convert:

- assertion-grade attribution into cryptographic actor proof;
- a synthetic provider-exit rehearsal into proof that private production data
  was exported;
- PostgreSQL 15/16 compatibility into PostgreSQL 17 compatibility;
- database portability into full hosted-product portability;
- SHA-256 integrity into signed authorship;
- core CI into HOUSE acceptance.

Record the final tag object/ref, exact commit/tree, asset hashes, final workflow
runs, independent review receipt, HOUSE acceptance receipt, and owner
authorization in the parent #55 closeout record.
